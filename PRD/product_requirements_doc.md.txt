## 1. Executive Summary

**ITravelista PH** is a web-first Progressive Web App (PWA) that helps Filipino tourists plan, prepare for, and manage international trips. It consolidates trip planning, visa requirement lookup, budget tracking, and smart checklists into a single mobile-optimized experience — replacing the current fragmented workflow of Facebook groups, spreadsheets, and multiple apps.

The MVP targets validation within a **4–6 week sprint** by a solo full-stack developer, focusing on four core features that prove the value loop: My Trips, Smart Checklist, Budget Planner, and Visa Assistant.

**Platform:** Web-first PWA (mobile-first responsive) → future native mobile via Expo/React Native
**Monetization:** Free at MVP — validate product-market fit first
**Target Launch:** Q4 2026

---

## 2. Problem Statement & Opportunity

### The Problem

Filipino tourists planning international trips face a fragmented preparation experience:

- **Visa requirements** are scattered across Facebook groups, embassy websites, and blog posts — often outdated or contradictory
- **Budget planning** happens in spreadsheets using foreign currencies, with no peso-denominated templates
- **Pre-trip checklists** live in Notes apps with no smart defaults — first-time travelers don't know what they don't know
- **Trip management** is split across TripIt (flights), Google Maps (itinerary), spreadsheets (budget), and group chats (coordination)

### The Opportunity

- **No dominant PH-specific travel companion app** exists in the market
- Filipino outbound tourism is growing 15%+ annually post-pandemic
- The Philippine passport has specific visa-free/visa-required countries — a focused, curated data set
- Filipino travel Facebook groups (millions of members) prove massive demand for consolidated travel advice
- A niche-first approach (PH passport holders → SEA expansion) creates a defensible market position

## 5. Technical Architecture Summary

> Full details in [architecture.md](./architecture.md)

### Stack

| Layer | Technology |
|-------|-----------|
| **Frontend** | Next.js 15+ (App Router) + TypeScript (strict mode) |
| **Styling** | Tailwind CSS v4 + shadcn/ui (Radix primitives) |
| **State** | TanStack Query (server state) + Zustand (client state) |
| **Backend** | Supabase (Postgres + Auth + Storage + Realtime) |
| **Validation** | Zod schemas at all API boundaries |
| **Charts** | Recharts or @visx/visx (donut chart) |
| **PWA** | @serwist/next (service worker + caching) |
| **Analytics** | Plausible (self-hosted) |
| **Deployment** | Self-hosted VPS + Coolify (Docker) |
| **Package Manager** | pnpm |

### Architecture Pattern

Feature-sliced architecture within Next.js App Router. Each feature module (trips, checklist, budget, visa, auth) is self-contained with its own components, hooks, actions, types, and utilities.

### Offline Strategy

- **Static assets**: Cache-first via service worker
- **API responses**: Network-first with IndexedDB fallback for last-viewed data
- **Writes**: Online-only for MVP. Clear "You're offline" indicator in UI.
- **Guest mode**: All data stored in localStorage (no server sync until signup)

## 6. Feature Specifications

### 6.1 My Trips

**User story:** As a Filipino tourist, I want to create and manage my upcoming trips so I can see everything in one place with countdown timers.

#### Functional Requirements

| Requirement | Detail |
|-------------|--------|
| **Create trip** | Title, destination (country picker with search), start date, end date, cover image (preset destination images) |
| **Trip card** | Cover image, destination, date range, countdown badge ("X days left"), status pill |
| **Trip list** | Tabs: Upcoming / Past. Sorted by start date (ascending for upcoming, descending for past) |
| **Trip detail** | Overview with navigation to Checklist, Budget, and Visa for that trip |
| **Trip status** | Auto-calculated: `planning` → `upcoming` (within 30 days) → `in_progress` (start_date ≤ today ≤ end_date) → `completed` (past end_date) |
| **Edit trip** | Modify title, dates, destination. Cannot change destination if checklist has auto-generated items (warn user). |
| **Delete trip** | Confirmation dialog. Cascades to checklist items and budget entries. |
| **Empty state** | Illustrated encouragement to create first trip with CTA button |
| **FAB** | "+ Add New Trip" pill-shaped floating action button, bottom-right anchored |

#### Edge Cases

- Trip with past `end_date` at app load → auto-set status to `completed`
- No limit on number of trips for MVP (monitor via analytics)
- Guest users: trips stored in localStorage, migration prompt on signup
- Duplicate destination in the same date range → allowed (user may have distinct trips)

#### Acceptance Criteria

- [ ] User can create a trip with all required fields
- [ ] Trip list displays upcoming trips sorted by start_date
- [ ] Countdown badge shows correct "X days left" calculation
- [ ] Trip status auto-transitions based on current date
- [ ] Deleting a trip removes associated checklist items and budget entries
- [ ] Empty state renders when no trips exist

### 6.2 Smart Checklist

**User story:** As a Filipino tourist, I want a pre-filled checklist for my destination so I don't forget any preparation steps.

#### Auto-Generation Logic

When a trip is created, the system generates checklist items from two sources:

1. **Universal items** (applied to every trip):
   - Passport (valid for 6+ months)
   - Flight Booking
   - Hotel/Accommodation Booking
   - Travel Insurance
   - Pocket Money / Foreign Currency
   - Print/Download Itinerary

2. **Destination-specific items** (from visa requirement data):
   - Visa Application Form (if visa required)
   - ID Photos (specific dimensions per country)
   - Proof of Financial Capacity
   - Certificate of Employment / Business Registration
   - Invitation Letter (if applicable)
   - Any country-specific requirements

Items are tagged with `is_auto_generated: true` and assigned appropriate categories.

#### Functional Requirements

| Requirement | Detail |
|-------------|--------|
| **Auto-generate** | On trip creation, populate checklist from universal + destination templates |
| **Manual items** | User can add, edit, and delete custom items |
| **Status tracking** | Three states: `todo` → `in_progress` → `completed`. Toggle via checkbox. |
| **Filter tabs** | All / To Do / In Progress / Completed (pill-shaped horizontal scroll) |
| **Progress indicator** | "X/Y completed" with percentage text and progress bar |
| **Categories** | `documents`, `booking`, `insurance`, `money`, `general` — icon + color per category |
| **Sort order** | Default: auto-generated first (by category), then manual items. Future: drag-to-reorder. |
| **View All** | Bottom CTA to expand collapsed items |

### 6.6 Authentication

**User story:** As a new user, I want to sign up quickly so I can start planning my trip without friction.

#### Supported Methods

| Method | Flow | Priority |
|--------|------|----------|
| **Google OAuth** | One-tap Google sign-in via Supabase Auth | P0 |
| **Magic Link** | Enter email → receive login link → click to authenticate | P0 |
| **Email + Password** | Traditional signup/login with email verification | P0 |
| **Guest Mode** | Skip login → use app with local storage only → prompt to sign up for sync | P0 |

#### Guest Mode Behavior

- All data stored in localStorage (trips, checklist items, budget entries)
- Banner at top: "Sign up to save your data across devices"
- On signup: migrate localStorage data to Supabase account
- On browser cache clear: data is lost (warn user)

#### Auth UI Screens

| Screen | Elements |
|--------|----------|
| **Login** | App logo, tagline, Google button, magic link input, email/password fields, "Continue as Guest" link |
| **Signup** | Same as login with password confirmation. Terms & privacy policy checkbox. |
| **Magic Link Sent** | Confirmation illustration, "Check your email" message, "Resend" link |

#### Acceptance Criteria

- [ ] Google OAuth completes full sign-in flow
- [ ] Magic link sends email and authenticates on click
- [ ] Email/password with validation (min 8 chars, email format)
- [ ] Guest mode stores data in localStorage
- [ ] Guest-to-authenticated migration preserves all data
- [ ] Session persists across browser sessions (refresh token)

## 9. Data Model Summary

> Full schema in [architecture.md](./architecture.md) § Data Model

| Entity | Key Fields | Relationships |
|--------|------------|---------------|
| **user** | id, email, display_name, auth_provider | 1:N → trip |
| **trip** | id, user_id, title, destination, country_code, start_date, end_date, status | 1:N → checklist_item, 1:N → budget_entry |
| **checklist_item** | id, trip_id, title, status, category, is_auto_generated, sort_order | N:1 → trip |
| **budget_entry** | id, trip_id, category, label, amount, currency | N:1 → trip |
| **budget_template** | id, destination, duration_days, entries (JSONB) | Read-only seed data |
| **visa_requirement** | id, country_code, visa_type, requirements (JSONB), fees, last_verified | Read-only seed data |

All tables use UUID primary keys, `created_at` / `updated_at` timestamps, and Row Level Security (RLS) to ensure users can only access their own data.

## 10. Non-Functional Requirements

### Performance

| Metric | Target |
|--------|--------|
| First Contentful Paint (FCP) | < 1.5s |
| Time to Interactive (TTI) | < 3.0s |
| Lighthouse Performance Score | > 90 |
| Lighthouse Accessibility Score | > 90 |
| Supabase query latency (p95) | < 200ms |
| Bundle size (initial JS) | < 150KB gzipped |

### Security

- All authentication via Supabase (OAuth2, PKCE flow)
- Row Level Security (RLS) on every user-facing table
- No PII in client-side logs or analytics events
- HTTPS everywhere (Coolify handles TLS via Let's Encrypt)
- Content Security Policy (CSP) headers
- `SUPABASE_SERVICE_ROLE_KEY` never exposed to client

### Accessibility

- WCAG 2.1 AA compliance (target, best-effort for MVP)
- All interactive elements keyboard-navigable
- Proper `aria-labels` on custom components (checkboxes, tabs, modals)
- Color contrast ratio ≥ 4.5:1 for all text
- Focus indicators on all interactive elements
- Screen reader-compatible navigation

### Offline

- Service worker caches static assets (cache-first)
- Last-viewed trip data cached in IndexedDB (network-first with fallback)
- Clear offline indicator: banner with "You're offline — showing cached data"
- Writes blocked offline with user-friendly message
- PWA installable on Android and iOS home screens

### Internationalization

- **Language:** English only for MVP
- **Currency:** PHP (₱) as default display. ISO 4217 codes stored in database.
- **Date format:** Locale-aware display (e.g., "May 10 – May 20, 2026")
- **i18n-ready:** Use string constants/keys (not hardcoded strings) to ease future Tagalog translation

## 11. Testing Strategy

### Approach: Inverted Diamond

Optimized for a solo developer — maximum confidence per hour invested.

| Layer | Tool | Priority | Coverage Target |
|-------|------|----------|-----------------|
| **TypeScript strict + Zod** | Compiler + runtime schemas | P0 — always on | 100% of API boundaries |
| **Unit tests (pure logic)** | Vitest | P0 | 80%+ for utils, calculations, template generation |
| **E2E tests (critical flows)** | Playwright | P0 | 3–5 core user journeys |
| **RLS policy tests** | Integration tests against local Supabase | P0 | All tables — verify data isolation |
| **Component tests** | Skip for MVP | — | — |
| **Visual regression** | Skip for MVP | — | — |

### Critical E2E Flows

1. **Signup → Create trip → View dashboard** — core onboarding
2. **Create trip → Auto-generate checklist → Check items** — checklist value loop
3. **Create trip → Apply budget template → Edit entries** — budget value loop
4. **Browse visa requirements → Check off items → "Add to checklist"** — visa flow
5. **Guest mode → Create trip → Signup → Data migration** — guest conversion

### Verification Pipeline

```
pnpm type-check    # TypeScript strict
pnpm lint          # ESLint
pnpm format:check  # Prettier
pnpm test          # Vitest (unit)
pnpm build         # Production build (catches SSR errors)
```

4. **Single integrated experience** — replaces 4+ tools with one PWA

## 14. Risks & Mitigations

| Risk | Severity | Likelihood | Mitigation |
|------|----------|------------|------------|
| **Visa data becomes stale** | High | Medium | Display "Last verified" dates. Link to official sources. Disclaimer on every page. Schedule monthly review. |
| **Low retention (travel is episodic)** | High | High | Add "dream trip" mode for aspirational planning. Budget savings tracker. Travel countdown widget for home screen. |
| **PWA limitations on iOS** | Medium | Certain | No push notifications on iOS PWA. Accept for MVP. Mitigate with email reminders. Native app in Phase 3. |
| **Feature scope creep** | High | High | Strict 4-feature MVP. All requests go to post-MVP backlog. No exceptions during sprint. |
| **Solo dev bottleneck** | Medium | Certain | Leverage shadcn/ui, Supabase, Coolify. Minimize custom code. Use AI pair-programming. |
| **Security breach (user data)** | High | Low | RLS on every table. No document storage at MVP (Phase 3). Supabase handles auth security. |
| **AI hallucination in visa advice** | High | N/A (MVP) | Not applicable — MVP uses static curated data only. AI deferred to Phase 2 with guardrails. |
| **App store rejection (future)** | Medium | Low | PWA-first strategy avoids this entirely. Native app when ready. |
